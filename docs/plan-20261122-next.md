Urutan eksekusi minggu depan, terpisah dari kronologi sesi
(`session-20261122-xnusys-homescreen.md`). Satu perubahan = satu eksperimen;
jangan flash tanpa approval; hanya `boot_a` + `xnusys`, slot A dicek sebelum/sesudah.

## 1. Selesaikan eksperimen GL=1 & pulihkan Android chainboot (`pstore`)

- Audit 2026-11-22 membuktikan 2 root cause:
  1. Bootloop Android chainboot (`NORET-BAKASU-1502`, `VERBOSE-LIVE-1548`) **bukan** dari `mtkloader` HEAD (`750bcc5`), melainkan `backup/boot_a.img` yang terpotong (ramdisk 34.5 MB & DTB hilang, 0 byte) + `tools/chainboot.py` belum mengecek panjang slice. **Fixed:** `backup/boot_a.img` dipulihkan dari `boot_bakasu_lto_20261121.img` (64 MB utuh) dan `tools/chainboot.py` diberi assert ukuran.
  2. Boot lambat 5.7+ menit sebelum `backboardd` spawn pada `GL1-1658` dan `VERBOSE-STOCK-1551` disebabkan flag `-v` (`vc_scroll_up()` ~10.4 MB/baris di `VM_WIMG_WCOMB`), bukan Mesa/panfrost.
  3. `userland/src/inject_sb.c` (`gpu_draws()`) ditambahkan fallback `IOServiceMatching("RedwoodMali")` menyamakan `inject.c`, dan `prebuilt/mach.development.bcm2837` disinkronkan ke kernel `bbcf6915`.
- Image siap uji baru (non-verbose, `loader_return_after=240`, `XNU_WATCH_SECONDS=420`):
  - `boot-images/xnu-selene-boot_a-CHAIN-BAKASU-GL1-RET240-20261122.img` (`MENU_DEFAULT_XNU=0`: default Android Bakasu → `./tools/boot-xnu.sh` → XNU GL=1 240s → kembali ke Android + `pstore` utuh).
  - `boot-images/xnu-selene-boot_a-XNUONLY-GL1-RET240-20261122.img` (`MENU_DEFAULT_XNU=1`: langsung XNU GL=1 240s → dump 64 KB log di layar `mtkloader`).
- Penentu sukses di log: `mali: step 6 of 6; user space says … N clients` dengan **N > 0**, `redwood: the server has an accelerated renderer`, tanpa fallback `softpipe`.

## 3. Dual boot tanpa PC — `github.com/oosexgang/hakios-uefi`

- Clone analisis: `/tmp/opencode/hakios-uefi` (tip 2026-11-21). U-Boot sebagai Android boot image
  (RAM-boot, pola chainboot kita) → EFI loader → **HKUB container dari SD-card FAT32** = pilih OS
  di HP tanpa fastboot. Ada USB recovery transport + perintah load image dari U-Boot → berpotensi
  nyeleniin problem observability (log tanpa Android hidup) dan problem chain Android bootloop.
- Realita: belum ada device profile apa pun ("There are no device profiles in this repository
  yet"); tiap board butuh profil DRAM map/DT/storage/USB DC/display (`docs/porting-a-board.md`);
  MT6769 belum ada board files di upstream U-Boot.
- Selene butuh U-Boot SETELAH LK (DRAM sudah di-init preloader) — GUESS, belum kebukti.
- Katalisator: profil Infinix **TD4160** (MT6769 sama, referensi Mali step 6 of 6) kalau muncul
  di portal — porting selene jadi jauh lebih murah.
- Langkah pertama kalau dikerjakan: profil `platform/xiaomi/selene/` (defconfig + overlay DT +
  `local-firmware/` DTB), tes RAM-boot **tanpa** sentuh GPT/partisi critical.

## 4. Eksperimen HP berikutnya (urutan lama, tetap berlaku)

1. Battery: `mtkbatt=1` + `bq2589x=1` (read-only, aman) — indikator baterai real
2. GPU depth: `metal=1` + `fbscale=3` — animasi/wallpaper Metal (butuh GL=1 sudah ada; lihat
   `userland/build.sh` METAL=1 + boot-arg `metal=1` + `RC=rc.launchd.metal`)
3. Connsys/scp (Wi-Fi/BT MT6631, accel SCP): butuh `pull-firmware.sh` dari Android — blokir
   sampai chain Android hidup
4. Bootloop chain Android: tersangka mtkloader HEAD (`750bcc5`) chain path — tes mtkloader
   `fd68492`-era (ekstrak blob NEWINIT `img[0:0x40000]`) + Image Bakasu + payload kini.
   Pstore capture (log semua run) terblokir sampai ini hidup.
